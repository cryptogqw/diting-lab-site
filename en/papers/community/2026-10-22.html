Paranoid EIP-8288: heterogeneous recursion with an authenticated class bank

In briefParanoid EIP-8288: heterogeneous recursion with an authenticated class bank

SummaryThe author describes a heterogeneous recursive aggregation scheme implemented in Parano1d, using a finite, authenticated bank of verifier classes so recursive steps can use several approved proof sizes. Small aggregates can use a smaller proving relation. The post explains how deferred matrix-evaluation claims are carried across classes and discusses how this could apply to the EIP-8288 aggregation backend, along with open questions.

Reveal optionality in encrypted mempools: how big is the sender’s free option, and a post-quantum way to remove it

In briefReveal optionality in encrypted mempools and a post-quantum way to remove it

SummaryThis forum post examines how much value a sender gains from controlling whether to reveal a transaction in an encrypted mempool, and why fees alone and forced opening do not fully remove this option. The author proposes Blind Simultaneous Release (BSR), which requires participants to commit before seeing new information and uses only hash functions, making it post-quantum. The accompanying paper has its theorems machine-checked in Lean 4, but the hardware speed assumption it relies on has not been measured.

Several projects to make merchant adoption easier and cheaper

In briefProjects to make merchant Bitcoin adoption easier and cheaper

SummaryThe author presents several projects built over two years to simplify merchant onboarding to Lightning. They include a CLINK plugin for Electrum that receives payments via nostr relays without opening ports, a plugin that automates obtaining inbound liquidity through submarine swaps, and a GUI for Electrum's swap server. The main project, BareBits, is merchant software that runs on simple web hosting or Windows desktops and is BTCPay-compatible. It charges a 1% fee and is described as open source and self-hosted.

SEACAST: fast, lean broadcast for Ethereum, with an executable spec and a formal model

In briefSEACAST: A Fast, Lean Broadcast Protocol for Ethereum With an Executable Spec and Formal Model

SummaryThe author proposes SEACAST, a protocol for quickly delivering large Ethereum messages. Nodes forward chunks as they arrive, and coding and sampling let each node receive only the parts it needs. The post reports that on 50 Mbps networks SEACAST is faster and uses fewer bytes than ECBroadcast and gossipsub, and it comes with an executable specification and a formal model.
